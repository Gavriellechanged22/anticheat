# Contributor Conduct

## Scope

This policy applies to issues, pull requests, reviews, discussions, Wiki
changes, project items, and other collaboration associated with this
repository.

## Required conduct

Participants must:

- keep communication professional, factual, and relevant to the technical
  scope;
- distinguish measured results from assumptions;
- provide reproducible evidence for defect and performance claims;
- address code and design decisions without personal attacks;
- follow maintainer decisions on repository scope, security boundaries, and
  change separation;
- remove credentials, signing material, private paths, user data, and kernel
  dumps from public submissions;
- use private vulnerability reporting for security-sensitive evidence;
- disclose conflicts of interest that materially affect a technical proposal.

Harassment, threats, discriminatory content, impersonation, deliberate
disruption, spam, and publication of another person's private information are
not accepted.

## Technical integrity

Contributors must not:

- falsify build, test, benchmark, or compatibility results;
- conceal security-relevant behavior in unrelated changes;
- submit generated or copied code without verifying its license and behavior;
- weaken warnings, branch protection, protocol validation, or security checks
  solely to make a change pass;
- publish production signing credentials or confidential vulnerability data.

## Enforcement

The repository owner may edit or remove content, lock conversations, reject
changes, or restrict participation when this policy or the documented
technical scope is violated.

Platform abuse should be reported through GitHub's reporting controls.
Vulnerabilities must be reported through
[private vulnerability reporting](https://github.com/amandykovxd/anticheat/security/advisories/new).
